# Качество ИИ-части: как мерили и что получилось

Задача: по свободному ответу клиента («зачем вы переводите и кто попросил?») узнать одну из 7 схем социальной инженерии или `none` — обычный перевод.

## Три режима
| Режим | Когда работает | Что внутри |
|---|---|---|
| **LLM** | есть ключ API и сеть | языковая модель, ответ строго по JSON-схеме (`app/tasks/scam_script.py`) |
| **Офлайн-классификатор** | без ключа или при сбое LLM — режим демо | TF-IDF по символьным n-граммам (2–5) + логистическая регрессия, обучается при старте на `app/tasks/data/scam_train.jsonl` (180 ответов); если модель не уверена (P < 0,3) — решают правила |
| **Правила** | если классификатор недоступен | ключевые слова и признаки давления |

## Данные
- **Обучающий набор** — 180 ответов, RU/KZ/транслит, написаны и размечены командой: `app/tasks/data/scam_train.jsonl`. На нём подбирали параметры кросс-валидацией (5 фолдов): C = 10, порог 0,3.
- **Тестовый набор** — 112 ответов, `evals/datasets/scam_script_test.jsonl`. Его писал **отдельный ИИ-агент (субагент Claude), которому не показывали ни правила, ни обучающие примеры**. Это снижает подгонку под собственный стиль, но не заменяет живых ответов: оба набора синтетические и написаны моделями одного семейства. По 12 ответов на каждую схему и 28 обычных, из них 16 «трудных» (сын, больница, брокерский счёт, арендодатель). Языки: 74 RU, 20 KZ, 8 смешанных, 10 транслит.
- Оба набора синтетические: реальных ответов клиентов банка у команды нет.

## Результаты на тестовом наборе
Замер сделан один раз после фиксации модели. Команда: `make eval`.

| Режим | Accuracy | Macro-F1 | Ловит мошенничество (recall) | Ложные тревоги на честных ответах |
|---|---|---|---|---|
| Правила | 0,64 | — | 61% (51 из 84) | 3 из 28 |
| **Офлайн-классификатор** (как в продукте) | **0,83** | **0,84** | **87%** (73 из 84) | 4 из 28 (14%) |
| LLM | не измерено — нужен ключ API | | | |

- Ложных тревог 4, а не 2 как у самого классификатора: ещё 2 добавляет страховка правил, которая не даёт модели «оправдать» текст с явными признаками схемы. Это осознанный выбор: лишний вопрос клиенту дешевле, чем пропущенная «служба безопасности».
- По языкам: RU 65/74, KZ 17/20, смешанный 5/8, транслит 7/10.
- Один раунд дообучения был: после первого замера (0,80) в обучающий набор добавили 32 примера на транслите и смешанном языке. Это сделано по агрегированной статистике, сами тестовые примеры не просматривались. Так на тесте получилось 0,83.

## Чего эти цифры не доказывают
- Набор маленький: ±1 пример меняет accuracy на 0,9 п. п.
- Ответы синтетические. На реальных ответах клиентов точность будет другой — поэтому первый шаг пилота — разметить обезличенные ответы.
- Ошибка ИИ не равна потерянным деньгам: перевод на счёт-дроп или с баллом ≥ 80 задерживается при любом вердикте модели (`docs/RISK_MODEL.md`).

## Как воспроизвести
```bash
make eval
```
Отчёт появится в `evals/reports/`. С ключом в `.env` та же команда измерит LLM-режим.

Последний отчёт `make eval` лежит в [`docs/eval/heldout_report.md`](eval/heldout_report.md).
