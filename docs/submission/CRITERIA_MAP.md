# Соответствие критериям оценки

Критерии взяты из правил ITU HACKATHON-2026 (`docs/CASE.md`).

| Критерий | Как Qorgan его закрывает | Доказательство | Слабое место (честно) |
|---|---|---|---|
| **Актуальность проблемы** | Фокус на схеме №1 в РК — звонках «от банка», где клиент переводит сам | 28,9 тыс. дел в 2025; 98% жертв сами передают данные (МВД); обход блокировки через второй телефон (АРРФР, авг. 2026) — `docs/research/RESEARCH.md` | Число дел в 2026 снижается (−22,4% за 9 мес.); ответ: давление смещается в обходы |
| **Инновационность** | Единый объяснимый поток: балл → градуированное трение → ИИ-разбор ответа → доверенное лицо → кейс для аналитика/АФЦ; оценка дропов до чёрного списка | Сравнение с Kaspi, «Второй рукой», ИИ-звонком НБРК, Т-Банком, BioCatch, Feedzai — слайд 7, `RESEARCH.md` §4 | Отдельные элементы на рынке есть; новизна — в связке и в обходе «второго телефона» |
| **Техническая реализация** | FastAPI + REST/OpenAPI, SQLite, ИИ со строгой JSON-схемой, фолбэк, инвариант «ИИ только ужесточает» | `app/qorgan/`, `app/tasks/scam_script.py`; 104 автотеста (74 — логика Qorgan); ruff, mypy --strict | Веса риска не обучены; LLM-режим не измерен без ключа; данные синтетические |
| **Качество ИИ** | Офлайн-классификатор на независимом тесте: 87% мошеннических ответов против 61% у правил | `docs/AI_EVAL.md`, `make eval` | Тест синтетический, 112 ответов |
| **Качество MVP** | Сквозной сценарий трёх ролей, 9 сценариев, состояния загрузки и ошибок, сброс демо, работа офлайн | Живое демо, `docs/media/qorgan_demo.mp4`, `DEMO_SCRIPT.md` | Веб-демо, а не мобильное приложение; сигналы телефона симулированы |
| **Практическая применимость** | Встраивается как модуль в платёжный поток; учитывает требования регулятора и закон о задержке до 5 дней | `INTEGRATION.md`: контракты, точки интеграции, безопасность данных | Нужны доступ к данным банка и обмен с АФЦ |
| **Масштабируемость** | Оценка без состояния; ИИ только для малой доли переводов; новые сценарии добавляются в схему | `ECONOMICS.md`: ≈ 43 000 ₸/мес на ИИ при 30 млн переводов; план до пилота | Нагрузочного теста нет |
| **Презентация** | Речь 5:00, демо 3:00, 15 ответов, резервный план | `SPEECH.md`, `DEMO_SCRIPT.md`, `JURY_QA.md`, `OFFLINE_PLAN.md`, `Qorgan_pitch.pdf` / `.pptx` | Нужна репетиция командой вслух с таймером |

## Соответствие FINTECH CASE

| Направление из кейса (цитата) | Как закрыто |
|---|---|
| «антифрод и выявление мошеннических операций» | балл риска и проверочный диалог, задержка перевода |
| «защиту клиентов и финансовых данных» | клиент получает объяснение схемы и совет; доверенное лицо получает сигнал без доступа к счёту |
| «повышение безопасности финансовых операций» | градуированное трение на исходящих переводах; ИИ не может выпустить перевод |
| «новые цифровые сервисы и технологии для банка» | сервис доверенного лица и консоль аналитика с объяснимыми кейсами |
| «предложите решение, которое действительно может улучшить безопасность, сервисы или процессы современного банка» | путь до пилота и точки интеграции — `INTEGRATION.md` |
