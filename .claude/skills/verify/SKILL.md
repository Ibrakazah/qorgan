# /verify

Цель — за 1–3 минуты ответить «готово или нет» фактами. Это не ревью (для него `/hard-review`), а проверка, что ничего не сломано.

## Фазы
Если в проекте есть `make check` или `npm run check`, сначала запусти его: он закрывает фазы 1–4 разом.
Команды бери из проекта: `package.json` (scripts), `Makefile`, `pyproject.toml`, README. В монорепо проверяй каждое приложение в `apps/*`, которое затронул diff. Фаза красная — дальше не идём: чиним (или зовём агента `build-error-resolver`) и запускаем `/verify` заново.

1. **Сборка:** `npm run build` / `make build` или аналог.
2. **Типы:** `npm run typecheck` или `npx tsc --noEmit`; для Python — `mypy` или `pyright`, если они настроены.
3. **Линтер:** `npm run lint`, `ruff check .` — если настроены. Предупреждения не блокируют.
4. **Тесты:** `npm test`, `make test`, `pytest -q`. Тесты, которые ничего не утверждают или помечены skip без причины, — отметь в отчёте.
5. **Запуск:** подними приложение в фоне без ключей (mock-режим), дёрни главный эндпоинт или открой страницу, проверь ответ и отсутствие ошибок в логах. Останови процесс.
6. **Секреты:** `git diff HEAD -- . ':!.claude' ':!tests'` без ключей (`sk-ant-`, `sk-[A-Za-z0-9_-]{20,}`, `AKIA`, `ghp_`, `github_pat_`), `.env*` не добавлены в git. Тестовые заглушки (`sk-test`, `test-key`) — не утечка. Нашёл ключ — стоп, сообщи пользователю, значение не печатай.
7. **Diff:** `git diff --stat`. Нет ли случайных файлов (логи, `dist`, большие бинарники), отладочного мусора и правок вне зоны текущей задачи из `docs/TASKS.md`.

## Отчёт
```
VERIFY: ГОТОВО | НЕ ГОТОВО
Сборка ✅  Типы ✅  Линтер ⚠️ 3  Тесты ✅ 41/41  Запуск ✅  Секреты ✅  Diff: 6 файлов
Чинить: 1) ... 2) ...
```
Если всё зелёное и пользователь не против — коммит с понятным сообщением.

## Правила
- Не отключай проверки ради зелёного статуса: никаких новых `skip`, `@ts-ignore`, `# type: ignore`, `--no-verify`.
- Фазу, которой в проекте нет (например, линтера), помечай «нет», а не «✅».
