# /ai-evals

Техническое жюри верит цифрам больше, чем словам. Цель — за 1–2 часа получить воспроизводимый отчёт одной командой.

## 1. Выбери 2–4 метрики под фичу
- **Классификация и модерация:** precision, recall и F1 по классам (особенно precision для классов, которые ведут к наказанию), confusion matrix.
- **Извлечение и структура:** доля ответов, валидных по схеме, точность по полям.
- **NPC и диалог:** доля действий, допустимых правилами игры; удержание роли (LLM-судья по рубрике 1–5); устойчивость к джейлбрейку (доля отказов на N атак); latency p50/p95; стоимость одного диалога.
- **Генерация контента (квесты, ивенты):** доля результатов, прошедших валидатор (предметы и локации существуют, награды в бюджете); разнообразие (доля дубликатов); оценка LLM-судьи.
- **ML:** ROC-AUC или F1 на отложенной выборке, важность признаков.

- **Поле-решение** (автозакрытие, бан, возврат): отдельный прогон по этому полю (в `ai-service`: `--target <поле>`). Precision класса «да» — это доля действий без ошибок, главная цифра для жюри.
- **Стоимость в масштабе:** стоимость одного вызова из отчёта × объём спонсора в день (из брифа) — строкой в README.

## 2. Собери датасет
- 30–100 примеров в `evals/datasets/<task>.jsonl`.
- Синтетику генерирует модель, но 20–30% примеров проверяет руками человек из команды; такие примеры помечаем `"verified": true`.
- Обязательно добавь трудные случаи: сленг, обфускацию, RP-контекст, атаки на промпт, пустой и очень длинный ввод.

## 3. Прогон
- В шаблоне `ai-service`: `python evals/run_eval.py --task <task> --dataset evals/datasets/<task>.jsonl`.
- В TypeScript-проекте: `scripts/eval-<task>.ts` по той же схеме: вход → вызов → проверка → метрики → markdown-отчёт.
- Кэшируй ответы модели, чтобы повторный прогон был бесплатным и детерминированным.

## 4. LLM-как-судья (если метрику нельзя посчитать кодом)
- Отдельный промпт с рубрикой, temperature 0, ответ строго по JSON-схеме.
- Если судья оценивает стиль, он не должен видеть эталонный ответ.
- Откалибруй судью на 5 примерах, размеченных руками, и напиши в отчёте, насколько он совпал с человеком.

## 5. Бейзлайн
Сравни с простым вариантом: эвристикой, правилами, старым промптом или моделью меньше. Прирост убеждает сильнее абсолютных цифр.

## 6. Отчёт
- Отчёт в `evals/reports/` (имя пишет скрипт): датасет, N, модель, метрики, примеры ошибок, команда для воспроизведения.
- В README — таблица «датасет | N | метрика | наш результат | бейзлайн» и одна команда для запуска.
- Честно укажи, что датасет синтетический или маленький. Цифры не округляй в свою пользу.
