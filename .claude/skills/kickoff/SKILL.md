# /kickoff

Цель — за 30–45 минут получить репозиторий, который запускается, задеплоен и содержит SPEC. Фичи кейса не пишем, пока скелет не работает.

## Шаги
1. Уточни у пользователя: имя проекта (kebab-case); шаблон (`web-game-3d`, `ai-service`, оба сразу — тогда монорепо `apps/web` + `apps/ai` — или `none`); публичным или приватным будет репозиторий; кому из команды нужен доступ.
2. Разверни проект из корня комплекта: `bash scripts/new-project.sh <name> <template> [<template2>]`. Скрипт копирует шаблоны, `CLAUDE.md` режима хакатона, скиллы, агентов и контекст, делает `git init` и первый коммит `chore: scaffold from team starter template`. Проект появится в `projects/<name>/`.
3. Скопируй всё, что есть в `cases/<slug>/` (`CASE.md`, `SPEC.md`, `PLAN.md`, `TASKS.md`, бриф), в `projects/<name>/docs/` и закоммить: `docs: add case, spec and plan`.
4. Установи зависимости и запусти проект по README шаблона. Убедись, что mock-режим работает. Создай `.env.local` или `.env` из `.env.example`; ключ пользователь вставит сам, его значение не печатай.
5. Замени README шаблона скелетом README проекта: вызови `/jury-readme` в режиме skeleton (название, одна фраза, разделы с TODO). README шаблона перенеси в `docs/TEMPLATE.md`.
6. **Только после явного «да» пользователя** (это публикация): `gh repo create <name> --private|--public --source . --push`; деплой фронта через `vercel` (preview), бэкенда — через Render, Railway или Docker. Ссылки добавь в README.
7. **Доступ для организаторов** (если по правилам нужен токен): fine-grained токен GitHub можно ограничить одним репозиторием — Settings → Developer settings → Fine-grained tokens → «Only select repositories» → этот репозиторий; права Contents: Read and write (Metadata: Read выставится сам); срок — день после дедлайна. Сам токен пользователь создаёт и передаёт организаторам лично, в чаты и модели его не вставляем.
8. **План до кода:** если `docs/PLAN.md` нет, предложи `/deep-plan`. Если есть — не планируй заново.
9. **Раздели работу:** если `docs/TASKS.md` уже есть (из `/deep-plan`), не перезаписывай его, только допиши владельцев и зоны. Иначе запиши в `docs/TASKS.md` первые задачи по ролям — у каждой владелец, зона файлов (папки не пересекаются между параллельными сессиями) и критерий «готово». Первая цель для всех — сквозной демо-сценарий к КТ-1.
10. Итог для пользователя: путь к проекту, ссылки на репозиторий и деплой, команды запуска, задачи из `docs/TASKS.md`. Последней строкой: «Дальше работаем из проекта: `cd projects/<name> && claude` — правила хакатона и guard-хук действуют только оттуда».

## Правила
- Первый коммит делаем после старта хакатона, с честным сообщением про шаблон.
- Если орги запретили заготовки, шаблоны из `templates/` не копируй: используй только публичные генераторы (`npm create vite@latest`, FastAPI с нуля).
- При параллельной работе у каждого участника или сессии своя зона файлов. Если нужно, заведи отдельный git worktree на ветку.
