# /submit-check

Пройди все пункты и дай отчёт: ✅ или ❌ по каждому, затем список того, что починить, по приоритету.

1. **Чистый клон.** `git clone <remote> "$TMPDIR/submit-check"`, затем выполни «Быстрый старт» из README буквально и засеки время. Работает ли без ключей (mock)?
2. **Секреты.** `git log -p --all -- . ':!.claude' ':!tests' | grep -nE "sk-ant-|sk-[A-Za-z0-9]{20,}|AKIA[0-9A-Z]{16}|(api[_-]?key|secret|token)\s*[:=]\s*['\"][^'\"]{8,}"`. Файлов `.env*`, кроме `.env.example`, в репозитории быть не должно; проверь `.gitignore`. Если ключ нашёлся в истории — СТОП: скажи пользователю немедленно отозвать ключ. Само значение не печатай. Тестовые заглушки (`sk-test`, `test-key`) и текст скиллов в `.claude/` — не утечка.
3. **Сборка и тесты.** build, typecheck, lint и тесты зелёные.
4. **README.** Все команды проверены, ссылки на демо и видео открываются, картинки рендерятся (пути относительные), таблица «кейс → решение» заполнена, цифры совпадают с отчётами эвалов.
5. **Демо.** Живая ссылка открывается в режиме инкогнито, мобильный вид не ломается, в консоли нет ошибок. Можно позвать агента `playtester`.
6. **Репозиторий.** Нет файлов больше 50 МБ, нет `node_modules`, `.venv` и `dist`; есть LICENSE (кладёт `new-project.sh`, проверь имя команды); на GitHub заполнены описание и topics; видимость и доступ для жюри соответствуют правилам.
7. **История.** Первый коммит сделан после старта из `.claude/context/hackathon.md`: `git log --reverse --format="%ad %s" --date=iso | head -1`. Коммиты осмысленные и распределены по времени хакатона; после дедлайна ничего не запушено.
8. **Тег** (только после «да» пользователя): `git tag -a submission -m "Hackathon submission" && git push origin submission`.
9. **Взгляд жюри.** Запусти агента `tech-jury` и добавь его топ-5 замечаний в отчёт.
